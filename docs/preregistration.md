## 1. 背景与目标
- 研究负责人的目标：用 BLT 式字节级潜在 patch 让模型①支持更长上下文、②降低推理成本、提高推理效率、③学到更有效的内部表示。最终要证明它**比传统 BPE transformer 更快，同时信息失真不过度**。尽量在已有方案上继续，允许直接改模型参数（参照 weight‑space programming 博客）。
- 资源：7500F + 32GB + RTX 4070 12GB。主线**规划 112 GPU 小时，另预留 28 小时（20%）**。GPU 可以连续使用，主线预计约 8–10 天跑完，剩下的时间按 §4 的预留优先级做扩展。所有任务都必须能随时暂停、可续跑。

## 2. 讨论过程：每轮改了什么
| 轮次 | 主要结论 |
|---|---|
| 1 | 核实了 7 篇论文（ID 全对）。两篇 10 月论文作者已在 v2.1.0 中收窄结论，撤回"novelty patching 改善散文 BPB"。Fast BLT 和 Scratchpad Patching 只报告 FLOPs 或估算带宽，**没有墙钟时间**；截至审查日，没有找到作者发布的实现或检查点（Fast BLT 有一个社区实现）。GPT 起初推荐在 Bolmo‑1B 上做压缩适配。 |
| 2 | **关键转折**：我和 GPT 各自独立算出 Bolmo‑1B 的局部模块（5 层、宽 2048 的 mLSTM，约 0.37 GFLOPs/字节）是瓶颈。要在 prefill 上追平只算最后一个 logit 的 OLMo‑1B，需要每个 patch 约 13–15 字节。Bolmo 论文里压缩到 6.2 字节/patch 时，核心任务分已掉约 5.8 分。 |
| 3 | 主证明改为"按成本模型设计的受控小规模实验"：局部模块很小，分 patch 严格因果，先过缓存一致性闸门再开训。 |

| 5 | 字节模型默认加**全局宽度的哈希 n‑gram 词汇通路**（只查表，不增加稠密投影）。Thin‑Bolmo 缩到 20 小时，只做接口恢复。增加 M‑16K BPE 强对照。"内部表示"用受控探针和扰动鲁棒性来测。 |
| 6 | 通读审查：预算和日期无误；修正了重复实验的数据量、Thin‑Bolmo 闸门、均匀分布测试值等，补全了配置冻结、分词器、BPB 定义、任务评测、种子、无人值守守护等规范；针对"前沿优势可能只是训练阶段造成的"增加了共同续训检查点。 |

## 3. 核心问题（可证伪）
> 在**相同的留出 BPB**（相差 ≤0.03 bit/字节，且相对 ≤3%）和可接受的任务表现下，字节潜在模型的实测推理性能是否优于我们训练出的**最强** BPE 模型？

允许得出否定答案。所有结论只引用实际训练出的检查点，不外推曲线，不用 FLOPs 或估算带宽代替墙钟时间。

## 4. 实验设计

### Track B：等质量速度前沿（主实验，68 GPU 小时）
- **实现**：新写一个紧凑的 PyTorch 实现。所有模型共用同一个 SDPA transformer block（RMSNorm、SwiGLU、RoPE；GQA 4 个 KV 头，**两个家族都用**，基线也强），用静态 KV 缓存，不依赖外部 CUDA 扩展。借用 BLT、Bolmo、segresearch 的边界语义和因果测试思路，但不移植它们的分布式框架。
- **模型**（参数为 GPT 计算、我复核过的数字，开训前由程序断言精确值）：

| 模型 | 全局：层/宽/Q头/KV头/FFN | 全局稠密参数 | 总参数 |
|---|---|---:|---:|
| S‑BPE 50K / 16K | 6/512/8/4/1536 | 18.9M | 44.6M / 27.3M |
| S‑byte P6 | 同 S‑BPE | 18.9M | 44.9M |
| S‑byte P8 | 8/512/8/4/1536 | 25.2M | 51.2M |
| M‑BPE 50K / 16K | 9/768/12/4/2048 | 56.6M | 95.2M / 69.2M |
| M‑byte P6 | 同 M‑BPE | 56.6M | 96.1M |
| M‑byte P8 | 11/768/12/4/2048 | 69.2M | 108.7M |

- **字节模型的局部部分**：编码 1 层、解码 2 层。宽度 S 为 128、M 为 192；局部头数 2/3；局部 FFN 384/512。按 64 字节块做局部因果注意力并带缓存。取已完成 patch 的最后一个状态，投影到全局宽度；全局输出每个 patch 投影回局部一次。
- **词汇通路（默认开）**：在 patch 结束处查 6 张哈希 n‑gram 表（n=3..8，每张 8192 行，全局宽度），按 1/√6 缩放求和后加在投影之后，在上下文起点重置哈希历史。这样绕开局部宽度的秩瓶颈，不增加稠密投影（但哈希计算、访存和优化器更新仍有开销，计入测速）。另做一个 **M‑P6 去掉哈希表的消融**。
- **配置冻结**：开训前把完整配置写成清单并由程序断言，包括字节词表和特殊 ID、嵌入共享、dropout=0、RoPE theta、最大位置、块边界重置行为和精确参数量。r=4.6 只是初始估计，以实测为准。
- **P8 模型的全局主干更深**，把省下的 FLOPs 重新投入容量（BLT 的论点），因此它是前沿上的一个点，不是干净的 patch 大小消融。
- **分 patch**：严格因果的分隔符规则。在已观察到的空格或标点之后切，最短长度在训练集上标定到实际 P≈6/P≈8，最长 16 字节或到块边界。不依赖未知的下一个字节。预测某个字节时，全局状态只来自已完成的 patch。
- **BPE 基线**：GPT‑2 50K（r≈4.6 字节/token）加 16K 词表对照。16K 分词器在固定、记录哈希的训练集样本上训练一次，S 和 M 共用；采用与 GPT‑2 相同的字节级预处理和正则，使词表大小成为唯一的主要差别；断言字节往返无损。prefill 只算最后一个 logit。
- **BPB 定义**：同一批文档窗口上，文本目标的总 NLL 除以（ln2 × 实际计分的 UTF‑8 字节数）。BOS/EOS 规则统一，不计 padding，不重复计分。分母不用 r 估算。Bolmo 的结果标注为"所选布局下的折叠 BPB"。
- **数据**：FineWeb‑Edu sample‑10BT，物化为 8–12GB 不可变的原始字节分片；按文档切分，验证集和测试集各 16MiB，不重叠，记录 SHA‑256。所有模型使用相同有序的 8KiB 窗口。**每个模型训练 3GB**（30 分钟 pilot 若达不到所需速度，开训前就把所有模型统一改为 2GB，写入预注册）。
- **重复与续训**：选定的 BPE/字节模型对（只按验证集选），seed 1 从头训到 3GB；然后 2 种架构 × 2 个种子各续训约 1.5 小时，得到约 3.75GB 的共同检查点，用来检验优势是否会随训练进程消失。去哈希消融在 0.75/1.5GB 的匹配检查点上比较。
- **种子**：初始化、数据顺序、分词器、哈希各用独立种子；数据顺序在各架构间固定。逐个种子报告；说明 bootstrap 区间不代表训练种子带来的不确定性。
- **训练**：AdamW（β 0.9/0.95，wd 0.1，嵌入不加 wd，裁剪 1.0），lr S 为 6e‑4、M 为 3e‑4，两个家族获得同样的短 lr 试探机会。有效 batch 64–128KiB。调度按步数或已消耗字节推进，不按墙钟。
- **GPU 小时分配**：S 三个模型 12、S‑16K 4、M 三个模型 21、M‑16K 7、重复（seed 1）14、共同续训 6、去哈希消融 4，合计 68。

### Track R：Thin‑Bolmo 接口恢复（20 GPU 小时，有闸门）
- 起点是 Bolmo‑1B（Apache‑2.0）。**残差宽度保持 2048**，只削局部计算：mLSTM 从 16 头选 4 头（Q/K 256、V 512），FFN 从 2816 降到 512，解码器从 4 层降到 2 层，边界投影降到 256。后缀嵌入表和 520 维输出头保留。目标局部成本约 0.057 GFLOPs/字节。
- **weight‑space programming 初始化（由我亲手做）**：按标定数据选头、选 FFN 通道，把对应的行和列一致地拷贝过去；线性映射用 SVD 作为第二种方案。对照是同结构的随机初始化，数据和训练设置完全相同。
- 训练：在原压缩率下，以未修改的 Bolmo‑1B 为在线教师做蒸馏。用教师强制的共同边界布局计算 520 维联合 KL，加上字节 CE 和边界监督，可选编码器状态匹配。全局冻结（必要时加 rank‑32 LoRA）。最终评测用学生**自己的路由**，不只报告教师布局下的 BPB。checkpoint 只存可训练增量。
- 8 小时 pilot 闸门：同布局下 BPB 差距 ≤0.10 且还在缩小；缓存和递归状态无误；显存留有余量。**不过就停**，剩下的小时数退回 Track B。强制 P 下的测速只作诊断，不作闸门。
- **不安排压缩适配**（论文已显示压缩代价大，我们的数据量只有约 1–3GB）。报告原压缩率下的接口恢复，以及 P=4.4/5.2/6 的速度上限。

### Track A：现有检查点基准 + 路由编程（3 GPU 小时）
- A1：Bolmo‑1B 对 OLMo‑2‑0425‑1B。测共同语料上的折叠 BPB、各领域实测 r、stock 路径和强制 P 下的速度上限，以及 KV 和状态统计。用来验证成本模型。
- A2（博客式，**由我直接读写权重，不用梯度**，≤1 GPU 小时、≤32 个标定 batch）：
  - Arm W：直接改现有张量，即 `boundary_predictor_module.q_proj_layer/k_proj_layer` 的 Q/K 对称化，以及 `lm_head` 边界与非边界成对行的方向编辑。
  - Arm P：手写 65536 项的字节对先验表。解码端在同一隐状态下严格保持字节的折叠概率。
  - 对照：只平移阈值的标量编辑。在 P 匹配到 ±3% 后比较 BPB 和数字、分隔符哨兵。所有编辑记日志、记张量哈希、可还原。

### 次要实验
- **解码（8h）**：先做 CUDA graph 捕获和状态一致性测试，两个家族都做；再在选定的小字节模型上试 BLT‑S 式自推测（k=4/8/16，greedy 输出须与逐字节生成完全一致）；BPE 一侧用已训练的小 BPE 做推测解码对照。加速不到 1.10 倍就停。MBP 只在有余量时用预留时间做。
- **长上下文（4h）**：选一对胜出的模型做续训，按原始字节计 50% 8KiB、25% 16KiB、25% 32KiB。测 8/16/24/32KiB 的检索（真实文本填充、留出的随机键、多个深度），分别在完整提示和固定物理 KV 预算两种设定下测。两个模型都失败时，只报告容量和内存，不声称"可用的更长上下文"。
- **内部表示（≤1 GPU 小时提取 + 约 4 CPU 小时）**：
  - 受控线性探针：数字奇偶和大小、形态后缀类别；在输入、中间、末层状态上做，配随机标签和未训练模型对照；按词元和数值划分出不相交的训练/测试集，因果前缀完全相同；为对齐而强制结束最后一个 patch 的做法只用于分析，并明确标注。
  - 扰动鲁棒性：无害的空白和大小写变化 vs 改变语义的数字编辑；测状态漂移、冻结探针准确率和超额 NLL。
  - 两项都有明确的失败条件（见 §5）。
- **预留时间的使用顺序**：正确性和恢复 → 主结果重复 → 更强 BPE 对照 → H‑Net 式学习路由续训（与第三个目标直接相关，4h）→ retrofit 扩展 → 推测解码或第三种规模。

## 5. 预注册结论与判定（测试集只在选择冻结后打开一次）
| 优先级 | 主张 | 通过条件 | 不过时怎么写 |
|---|---|---|---|
| **主** | 等质量下 prefill 更快 | ΔBPB ≤0.03 且 ≤3%；8/16KiB 下 ≥1.20 倍；计时 CI 不含 1；选定的点有重复 | 报告实测的权衡前沿，不声称占优 |
| **主** | 任务保持 | PIQA/HellaSwag 合计降幅 ≤2 分（模板、少样本设置和子集事先冻结；用候选答案的对数似然打分，两个家族用同一归一化规则，同时报告未归一化准确率；BPE 包装与参考 harness 交叉核对；接近随机水平时不支持结论） | 只声称 BPB 层面 |
| 次 | 批量解码更快 | 预注册的 batch（8 或 32）下 ≥1.20 倍 | 标题只写 prefill |
| 次 | batch‑1 延迟 | 对最强的 BPE 解码（含 graph 和推测解码）≥1.10 倍 | 明确报告字节解码更慢 |
| 次 | 更长的可用上下文 | 同等物理缓存下多装 ≥1.25 倍字节，检索 ≥90%，降幅 ≤5 分 | 只声称内存和容量 |
| 次 | 内部表示 | 探针在两个属性上有 ≥3 分的受控提升并能重复；无害扰动下超额 NLL 低 ≥20%，且对数字改动仍敏感 | 报告无证据 |
| 次 | Thin‑Bolmo / WSP 初始化 | 与教师的差距 ≤0.03 BPB；编程初始化比随机初始化少用 ≥25% 恢复数据量 | 报告恢复失败或没有节省 |
| 次 | 路由编程 | P 匹配时 BPB 改善 ≥0.01，哨兵不退化 | 报告有限的负结果 |

- **额度用完就暂停**：不再调用 GPT，正在跑的任务存档后停下，写状态说明并通知研究负责人。

## 8. 基础设施、环境与下载（公开版删节）
- **可抢占**：
  - 全局暂停标志，每 10 秒检查一次；收到暂停就做完当前这一步、保存并退出，≤60 秒内释放显存。不设固定时间窗口。
  - 保留两个滚动 checkpoint。续跑后，采样哈希和计数器必须完全一致，损失在声明的数值容差内一致（阶段 0 预检时验证；软件版本锁定；不承诺非确定性 kernel 下逐位相等）。
  - 测速只在 GPU 空闲时段单独进行。发现其他程序在用 GPU 就暂停让路。
- **无人值守**：队列守护进程带单实例锁、心跳，出故障时默认暂停。
- **运行环境**：Windows 上的 WSL2（Ubuntu 24.04）。
- **Python 3.12 环境**：PyTorch 2.9.1 CUDA 版、transformers 4.57.3、xlstm 2.0.5、mlstm‑kernels 2.0.2、tokenizers、datasets、safetensors、matplotlib、scikit‑learn，约 5–6GB。
- **代码**：git clone allenai/bolmo‑core（Apache‑2.0），nicoveraz/segresearch（MIT，仅作参考）。
- **模型和数据（Hugging Face）**：
  - allenai/Bolmo‑1B（约 5.9GB）、allenai/OLMo‑2‑0425‑1B（约 5.9GB）、GPT‑2 tokenizer。
  - FineWeb‑Edu sample‑10BT 的若干 parquet 分片（约 10–15GB，用于物化 8–12GB 训练字节）。
  - PIQA/HellaSwag 评测集（<0.2GB，ARC‑E 先不用）、allenai/bolmo_mix 小样本（≤0.2GB）。
  - 下载约 35GB；算上环境、缓存和 checkpoint，峰值按约 100GB 预留。不下载 BLT 门控权重，不下载 17.6GB 的 olmo_core 检查点。
- **存放位置**：代码仓库（本地 git）、环境、数据和检查点都放在 WSL 的 ext4 文件系统里。

## 9. 主要风险（按严重度）及最早的检验
1. 质量差距吃掉速度优势：看 0.375GB 时的 S 检查点。
2. Thin‑Bolmo 无法恢复：用 8 小时 pilot 闸门。
3. FLOP 节省被池化、哈希、launch 开销吃掉：阶段 0 用随机权重测速，第一个检查点出来后测端到端。
4. 边界或评分泄漏、缓存状态错误：开训前做前缀不变性、未来字节扰动、全量与增量一致性测试。
5. 续跑改变了样本或调度：连续 20 步对比 10 步 + 存取 + 10 步。
6. 基线太弱：用 50K 和 16K 两种词表，两边都用 GQA 和融合注意力，prefill 只算最后一个 logit。
7. 长上下文检索没有信息量：先测未改动的检查点，8KiB 都不过就不投入续训。

## 10. 交付与验证
- **每天**：一条中文决策记录（实测字节/秒、已用的唯一字节数、BPB、实际 P、峰值显存、续跑状态、接下来的队列、剩余预算）。
